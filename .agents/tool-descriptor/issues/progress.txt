2026-07-31T09:30:00Z issue-td-04-task-inputs-strict-binding: DONE
- `annotations.py`: added `Input[T] = Annotated[T, _InputMarker()]`, mirroring `Param`. Purely for authors who want to say "task input" explicitly — `_unwrap` already strips any `Annotated[...]` regardless of marker, so `Input[T]` and a plain unannotated parameter are indistinguishable to the binder.
- `descriptor.py`: `ToolDescriptor.bind` reclassifies every non-`Task`/`ExecutionContext`/`Param[T]` parameter as a task input (previously: `TypeError("not yet implemented")`). New `ToolBindingError(Exception)` — raised, not `TypeError`, so callers can catch it specifically. Renamed the dataclass `ToolParam` -> `ToolField` (name/type_hint/optional) since it's now shared by both `.params` and the new `.inputs` cached_property. Strictness, only for non-opaque tools:
  - Before binding starts, every name in `task.inputs` must be a known input parameter, else `ToolBindingError` naming the extra input.
  - Per input parameter: `task.get_input(name)` missing -> falls back to the parameter's default (or `None`); present -> uses `.value` (mirrors `get_param_value`'s "object present -> its value, even if None; object absent -> default" semantics, for consistency with `Param` binding).
  - `optional` = has a default or the annotation unwraps to `Optional[...]`. A resolved value of `None` on a non-optional input raises `ToolBindingError`, naming the input and its `get_from` key (`task.get_input(name).get_from`) when the input was declared but simply resolved to nothing.
  - Opaque (`Task`-typed) tools are exempt from every check above — both the "unknown input" pre-check and the per-parameter None-check are gated on `not self.opaque`.
  - `.inputs` (new): same shape as `.params`, listed in `to_dict()` under an `"inputs"` key (omitted when empty, same convention as `params`/`outputs`).
- `launcher.py`: `AgentLauncher._execute_task` now has a first `except ToolBindingError` clause (before the general `except Exception`) producing `TaskError(code="TOOL_BINDING_ERROR", message=str(e), ...)`; the pre-existing generic clause still produces `TOOL_FAILURE` for everything else. Binding happens inside `base_agent.execute_task`, outside its tool-invocation try/except, so a `ToolBindingError` from `descriptor.bind()` propagates unmodified up to the launcher — no change needed in `base_agent.py`.
