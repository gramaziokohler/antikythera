- `descriptor.py`: hand-rolled NumPydoc parser, no new dependency. `_docstring_section_spans(lines)` finds each section's header structurally — any non-indented, non-blank line immediately followed by a line made entirely of `-` characters — and maps section name -> `(content_start, content_end)` line range; this needs no hardcoded list of NumPydoc section names (`Parameters`, `Returns`, `Raises`, ...) since it only ever looks up `"Parameters"`/`"Returns"` by key. `_parse_field_list(lines, start, end)` walks a section's body: a non-indented line starts a new field (name taken as the text before the first `:`, comma-split to handle NumPy's shared-description `x1, x2 : int` shorthand), every indented line beneath it is appended to that field's description and joined with single spaces (`" ".join(" ".join(current_desc).split())`, so both the multi-line join and internal whitespace collapse happen in one pass) — a field with a header line but zero description lines is dropped (`flush()`'s `if current_names and current_desc` guard), which is what makes io.copy's existing unnamed `Returns` block (`dict\n    Dictionary containing ...`) degrade harmlessly rather than fabricate a bogus field named "dict". `_parse_numpy_docstring(doc)` ties it together: `None`/empty docstring or a missing section each yield `{}` for that side, never an exception — degrade-don't-fail is structural here (pure string/list indexing, no parsing state that can throw) rather than a wrapped try/except.
- New `ToolDescriptor._field_descriptions` cached_property: `(param_descriptions, return_descriptions)` from `_parse_numpy_docstring(inspect.getdoc(self.func))`, computed once and shared by `params`/`inputs`/`outputs`.
